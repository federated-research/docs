# Computational Patterns
There are many ways to undertake federated analysis or federated learning and each has benefits and limitations.

Our work has shown that despite the significant number of federated tools, algorithms and platforms, when you examine 
the patterns for how these analyses are undertaken they can be simply grouped on two dimensions: their **Analytical** and **Data movement** patterns.

## Analytical patterns

There are three key concepts that summarise the vast number of analytics and learning that are possible when data is spread across multiple TREs:

| Analytical pattern | Description |
| ------------------ | ----------- |
| Isolated           | Analyses that are replicated individually within each TRE. |
| Connected          | Analyses that require multiple rounds of local calculation and aggregation, requiring the TREs to receive results from other TREs to be included in the local calculations. |
| Centralised        | Analyses require data to be pooled, even temporarily, for the analyses to be performed. |

## Data Movement patterns
As determined by the algorithm type, this is how data is required to move in and out of a TRE and how it is executed.

| Data Movement pattern | Description |
| --------------------- | ----------- |
| Summary               | A statistical result is shared back that does not relate to any individual but is a calculation based on the confidential data. It is the summary result that moves from the TRE. |
| Model Parameters      | A machine learning algorithm runs on the data at each TRE, and the weights are moved from the TRE. |
| Row level data        | Row level data moves, whether or not it is anonymised. Each data element is at the level of an individual. |


## Connections
The patterns we have identified to date indicate that the type of analysis to be run dictates the type of data to move.
It is important to state that these classifications of the data movement do not indicate the disclosive data of a specific result.
Summary results are inherently less likely to be disclosive than row-level data but outputs must be assessed based on each TRE's [egress](./egress) procedures.

| Analytical | Data Movement | 
|-|-|
| **Isolated** | Summary only | 
| **Connected** | Model Parameters | 
| **Centralised**| Row level data only |
